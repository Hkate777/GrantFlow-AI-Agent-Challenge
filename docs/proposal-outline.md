# 參賽計劃書大綱（對應官方計劃書內容要求）

> 用途：初賽提交 PPT 的內容骨架。每條均已映射到官方「計劃書內容要求」四項與評審四維度。

## 1. 項目基本信息
- 項目名稱：**GrantFlow · 申請評審與項目管理流程自動化 Agent**
- 賽道：指定賽道 · 教育與文化創意 · **場景 16**（校內行政工作流搭建方向）
- 團隊：KK_Garden（2 人）
  - 成員 A（隊長）：Agent 架構與工作流編排、評審規則引擎
  - 成員 B：多格式文檔解析、Web 面板與 Demo 製作
- 一句話簡介：讓機構每年上千份異構申請材料的受理、審查、評審與追蹤，從「人找問題」變為「Agent 推送結論」。

## 2. 業界痛點與業務挑戰
- 大學/科技園/創投機構每年處理大量異構申請：文字報告、簡報、試算表、影像、財務資料、證明文件格式不一
- 各計劃要求、格式、準則、資格不同，人工核對耗時長、易遺漏
- 評審評分分散、分歧缺乏系統識別；評審後項目跟蹤靠表格+郵件，逾期無人發現
- 目標客户：高校科研處、創科園區運營方、政府資助計劃秘書處、創投機構
- 典型案例：某計劃 800 份申請 × 平均 6 份附件，人工初審 3 周 → GrantFlow 分鐘級完成初審並給出需人工複核清單

## 3. 技術解決方案
- **Agentic Workflow**：Ingest → Extract → Check → Verify → Summarize → Review → Track 七段流水線（見 docs/architecture.md）
- **聲明式計劃規則引擎**：計劃差異用 YAML 描述（必填字段/附件/資格/評審準則/利益衝突/預算上限），新計劃零代碼接入 —— 直接回應場景 16「各計劃要求各不相同」的核心難點
- **LLM + 規則混合**：LLM 負責非結構化抽取與摘要，規則引擎負責硬性核查，確定性問題不交給概率模型
- **跨源交叉驗證**：表單 vs 申請書數值/標題/郵箱比對；批次級查重 + 穩健離羣檢測（中位數 ± 5×MAD）
- **評審彙總**：維度加權百分制、分歧自動識別（差值閾值可配）、複議建議、結果通知與待辦生成
- **人機協同**：所有關鍵節點輸出 `needs_human` 標記；全程審計日誌可復現
- **創新點**：① 聲明式多計劃適配；② MockLLM 離線確定性復現 + 可插拔真實 LLM；③ 審計即產物（AuditTrail 貫穿全鏈路）；④ 各子 Agent 可封裝為獨立 Skill/MCP 工具複用

## 4. 預期成果
- 效率：單份申請初審從 30 分鐘 → < 1 分鐘；批次 100 份 < 10 分鐘（可量化基準測試隨附）
- 質量：缺失/矛盾/異常檢出率 ≥ 95%（以 demo 內置異常集迴歸驗證）
- 落地路徑：校內科研管理處試點（場景 16 校內行政工作流）→ 創科園區 → 創投機構；按 SaaS 訂閲 + 計劃配置服務費商業化
- 社會價值：減少行政重複勞動，讓評審資源聚焦實質創新；提升資助發放透明度與可追溯性
