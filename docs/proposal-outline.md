# 参赛计划书大纲（对应官方计划书内容要求）

> 用途：初赛提交 PPT 的内容骨架。每条均已映射到官方「计划书内容要求」四项与评审四维度。

## 1. 项目基本信息
- 项目名称：**GrantFlow · 申请评审与项目管理流程自动化 Agent**
- 赛道：指定赛道 · 教育与文化创意 · **场景 16**（校内行政工作流搭建方向）
- 团队：KK_Garden（2 人）
  - 成员 A（队长）：Agent 架构与工作流编排、评审规则引擎
  - 成员 B：多格式文档解析、Web 面板与 Demo 制作
- 一句话简介：让机构每年上千份异构申请材料的受理、审查、评审与追踪，从「人找问题」变为「Agent 推送结论」。

## 2. 业界痛点与业务挑战
- 大学/科技园/创投机构每年处理大量异构申请：文字报告、简报、试算表、影像、财务资料、证明文件格式不一
- 各计划要求、格式、准则、资格不同，人工核对耗时长、易遗漏
- 评审评分分散、分歧缺乏系统识别；评审后项目跟踪靠表格+邮件，逾期无人发现
- 目标客户：高校科研处、创科园区运营方、政府资助计划秘书处、创投机构
- 典型案例：某计划 800 份申请 × 平均 6 份附件，人工初审 3 周 → GrantFlow 分钟级完成初审并给出需人工复核清单

## 3. 技术解决方案
- **Agentic Workflow**：Ingest → Extract → Check → Verify → Summarize → Review → Track 七段流水线（见 docs/architecture.md）
- **声明式计划规则引擎**：计划差异用 YAML 描述（必填字段/附件/资格/评审准则/利益冲突/预算上限），新计划零代码接入 —— 直接回应场景 16「各计划要求各不相同」的核心难点
- **LLM + 规则混合**：LLM 负责非结构化抽取与摘要，规则引擎负责硬性核查，确定性问题不交给概率模型
- **跨源交叉验证**：表单 vs 申请书数值/标题/邮箱比对；批次级查重 + 稳健离群检测（中位数 ± 5×MAD）
- **评审汇总**：维度加权百分制、分歧自动识别（差值阈值可配）、复议建议、结果通知与待办生成
- **人机协同**：所有关键节点输出 `needs_human` 标记；全程审计日志可复现
- **创新点**：① 声明式多计划适配；② MockLLM 离线确定性复现 + 可插拔真实 LLM；③ 审计即产物（AuditTrail 贯穿全链路）；④ 各子 Agent 可封装为独立 Skill/MCP 工具复用

## 4. 预期成果
- 效率：单份申请初审从 30 分钟 → < 1 分钟；批次 100 份 < 10 分钟（可量化基准测试随附）
- 质量：缺失/矛盾/异常检出率 ≥ 95%（以 demo 内置异常集回归验证）
- 落地路径：校内科研管理处试点（场景 16 校内行政工作流）→ 创科园区 → 创投机构；按 SaaS 订阅 + 计划配置服务费商业化
- 社会价值：减少行政重复劳动，让评审资源聚焦实质创新；提升资助发放透明度与可追溯性
