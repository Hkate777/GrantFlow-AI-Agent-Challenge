# GrantFlow v1.1.0

「智賦香江」AI智能體應用大賽 · 指定賽道 · 場景16（教育與文化創意賽道 · 校內行政工作流方向）

參賽隊伍：KK_Garden

此版本在 v1.0.0（批次全流程）之上，完成兩條開發線的融合：加入可逐步操作個案的 **Web 工作台**、**人工簽發狀態機**、**本機帳號與權限**、**資助台帳校驗**，並修復第三輪審評的實測缺陷。測試由 96 項全數通過。

## 相對於 v1.0.0 的新增能力

### 1. Web 工作台與個案生命週期

- 網頁表單、`.eml` 郵件附件、資料夾三種收件渠道（`/api/mail` + `submission.read_message`）
- 個案狀態機：`待補件`、`資格待核`、`待評分`、`評分待更正`、`待複議`、`評審人數不足`、`待人工覆核`、`待簽發`
- 補件、評分、複議記錄、人工簽發各有版本號防衝突（`revision`），過期操作被拒絕
- 前後端分離：FastAPI `create_app()` 工廠 + `web/` 前端（近 20 個 API 端點）

### 2. 人工簽發與負責任AI

- **正式結果通知只在工作台由人簽發**：`assess()` 的 `notice` 恆為 `None`；命令行與 Excel 只寫評審進度草稿
- 截止時間以服務端收件時間 `received_at` 為準，不再採信申請人自報日期，逾期申請阻斷簽發
- `Program.min_reviewers`（內置計劃均為 2）：評審人數不足產生 `insufficient_reviews` hold，簽發被擋
- 程序快照隨案：個案保存 `program_snapshot`，簽發時鎖定規則版本，配置更新或移除後歷史評審包仍按原規則重建

### 3. 帳號與身份

- 本機帳號、HTTP Basic 登入、scrypt 加鹽口令
- 所有 `/api` 需身份驗證；審計事件綁定服務端操作員，前端自填 actor 已忽略
- 停用帳號即時撤銷全部工作階段（`GET /api/auth/me` 可驗證）

### 4. 資料與證據

- `evidence.py`：欄位原文位置佐證（出處行號與引文），中英日標籤別名 + 繁簡容錯
- `money.py`：港幣金額嚴格解析（千/萬/百萬/億、HK$、港元）
- 資助台帳寫入校驗：撥款合計不得超出核准額度、禁止未來確認日期、往返一致性（P0-11）

### 5. 工程質量

- 兩條開發線融合，保留 main 線的多地區/私隱/多模型與工作台線的工作台/存儲/證據，無重複代碼
- 依賴版本鎖定，隔離 venv 乾淨安裝可跑通全部測試
- 模組 docstring 與流程表述統一為香港繁體，修復被損壞的流程箭頭表述

## 對應場景16官方功能要求

| 官方功能要求 | 對應模塊 | 本版增強 |
|---|---|---|
| ①多渠道收集申請資料及附件 | `ingest.py` + `submission.py` | 新增網頁/`.eml`/資料夾三渠道與安全收件校驗 |
| ②按個別計劃要求檢查完整性及合規 | `check.py` + `program.py` | 程序快照 + 截止以收件時間為準 + 地區規則 |
| ③識別缺失、重複、錯誤或異常 | `extract.py` + `evidence.py` | 新增原文位置佐證與港幣金額解析 |
| ④生成標準化摘要、一頁簡介、評審資料包 | `summarize.py` | 對外評審包去識別化 |
| ⑤彙總評語與評分、識別分歧 | `review.py` | 新增 `assess` 狀態機 + 評委人數下限 + 人工簽發 |
| ⑥結果通知、待辦、項目追蹤 | `review.py` + `track.py` | 新增台帳寫入校驗與規則版本快照 |
| ⑦異常預警及管理報告 | `track.py` | 兩級預警 + 管理報告 |

## 快速開始

```bash
pip install -r requirements.txt
python cli.py                 # 命令行一鍵跑通全流程（離線、無需 API Key）
python app.py                 # Web 工作台 http://127.0.0.1:8000
python -m pytest tests -q     # 96/96
python scripts/pitch_demo.py  # 一鍵生成決賽演示全套物料
```
